The Phase 4 implementation is present, but the checkpoint is not complete until the missing provider-application integration coverage is added.

Add focused API integration tests for:

1. Provider application ownership
   - User A cannot read User B’s application.
   - User A cannot update User B’s application.
   - User A cannot submit User B’s application.
   - Admin behavior remains governed by existing admin permissions.

2. Idempotent onboarding
   - Starting provider onboarding twice creates one provider membership.
   - Starting provider onboarding twice creates one provider profile.
   - Starting provider onboarding twice creates one draft application.
   - Repeating the request returns or resumes the existing application.
   - Concurrent onboarding requests do not create duplicates.

3. Draft updates
   - Authenticated owner can save valid draft profile data.
   - Invalid fields are rejected with stable validation errors.
   - Draft updates do not grant provider operations.
   - Draft updates preserve unrelated client access.

4. Submission validation
   - Incomplete provider applications cannot be submitted.
   - Complete applications transition to under_review.
   - Submitting twice is idempotent or returns the documented conflict.
   - Rejected applications can resubmit only through the approved path.
   - Suspended applications cannot bypass the suspension state.

5. Authorization escalation prevention
   - roleIntent=provider never grants provider operations.
   - A provider membership without an approved application remains blocked.
   - An approved application with an unapproved provider profile remains blocked.
   - Draft, under_review, rejected, and suspended states remain blocked.
   - Only approved application plus approved provider profile grants provider operations.
   - Provider credential submission does not grant provider portal access.
   - Client-controlled active-role or query parameters cannot bypass server authorization.

6. Existing-user flow
   - A client can start “Become a provider” using the same account.
   - Existing client membership remains intact.
   - Existing bookings and care history remain accessible.
   - Repeated requests do not create duplicate records.
   - Provider operations remain blocked until approval.

7. Privacy regression
   - Provider-private careNotes remain absent from client responses.
   - Provider application reviewer notes and private verification details are not exposed to ordinary clients.
   - Unrelated users cannot inspect another user’s onboarding data.
