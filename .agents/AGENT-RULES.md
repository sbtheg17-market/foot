# Agent Rules — OnCall Foot

These rules apply to **every agent session** on this repository, regardless of platform or agent type. Read them before writing any code.

---

## 1. Read Before You Write

Every session starts with three reads — no exceptions:

1. **`.agents/LOG.md`** — what was last done and where to resume
2. **`replit.md`** — full project context, current build state, all commands
3. **`docs/product-vision.md`** — the mission; every feature decision flows from here

For domain-specific work, also read the relevant doc:
- Auth / permissions → `docs/roles-and-permissions.md`
- Booking logic → `docs/booking-statuses.md`
- DB shape → `docs/data-models.md`
- API surface → `docs/api-routes.md`
- UI / frontend → `docs/ux-guidelines.md`
- Deployment → `docs/deployment-notes.md`

---

## 2. Always Append to the Log

Before your session ends, append a new entry to `.agents/LOG.md` and update the **Current Build State** table. A session that does not log its work does not exist for the next agent.

See the template at the bottom of `.agents/LOG.md`.

---

## 3. Write Commit Messages That Serve the Cause

See `docs/checkpoint-notes-guide.md`. The short rule:

> Every commit message answers: *"What got better for the user?"*

---

## 4. Mobile First — Always

The primary users are on phones. Every UI decision starts at 390px. See `docs/ux-guidelines.md` for the full checklist. Never ship a screen without verifying it on a mobile viewport.

---

## 5. API Contract First

Before implementing any new endpoint:
1. Add it to `lib/api-spec/openapi.yaml`
2. Run `pnpm --filter @workspace/api-spec run codegen`
3. Then implement the route

Never implement a route that isn't in the spec. The spec is the contract between backend and frontend.

---

## 6. Never Edit Generated Files

Files under these paths are auto-generated by Orval. Never edit them manually:
- `lib/api-zod/src/generated/`
- `lib/api-client-react/src/generated/`

Run codegen to regenerate them after spec changes.

---

## 7. Prices in Cents

All monetary values in the database and API are stored as integers in cents. Never use floats for money. Never store dollars.

---

## 8. Booking Status Transitions Are Strict

Enforce only the allowed transitions defined in `docs/booking-statuses.md`. Any route that changes booking status must validate the transition before writing to the DB. Admin can override — no one else can.

---

## 9. Secrets Are Secrets

Never log, print, or commit secret values. `JWT_SECRET`, `DATABASE_URL`, and any future keys live in environment secrets only. On Replit: use the Secrets tool. On other hosts: set as env vars in the host's dashboard.

---

## 10. No Replit Lock-in in Application Code

Application code (anything under `artifacts/api-server/` and the future `artifacts/web/`) must not import `@replit/*` packages. Those belong only in `artifacts/mockup-sandbox/` (the design tool, never deployed).

---

## 11. Keep This File and the Log Portable

`.agents/LOG.md` and `.agents/AGENT-RULES.md` are committed to the repository. They must remain plaintext Markdown, with no Replit-specific tooling required to read them. Any agent, on any platform, must be able to read and append to them with a standard text editor or file write tool.
